# The Unplugged Wear — Database Schema Overview

> Status: Active | Last Updated: 2026-11-10
> Replaces the earlier microservices / MongoDB / Redis design, which is
> retired. This page is the map; the SQL files and `DOC/backend/` are the
> detail.

## 1. One database, two apps

- **Engine:** PostgreSQL on **Neon** (one database; Neon branches for
  preview and development copies).
- **Shared by:** `tuw-website` (storefront API) and `tuw-admin` (admin
  API). Neither app owns the schema.
- **Source of truth:** `db/migrate/*.sql` (applied in file order) and
  `db/seed/001-seed-core.sql` (re-runnable, no secrets, no fake data).
  If a document disagrees with the SQL, the document is wrong.
- **No MongoDB, no Redis in v1.** CMS content is `jsonb` in Postgres;
  caching can be added later without changing the schema.

## 2. Conventions

UUIDv7 primary keys · money `DECIMAL(12,2)` rupees with `CHECK >= 0` ·
statuses as `varchar` + `CHECK IN (…)` · real foreign keys everywhere ·
an index on every foreign key · `timestamptz` created/updated pair on
mutable rows · snake_case plural table names · secrets only in env.
Detail: `DOC/backend/01-Conventions.md`.

## 5. Rules that live in the database

- **Guest or account order, never half of each** (`orders_buyer_identity`).
- **No oversell:** atomic `UPDATE … WHERE stock >= qty` at checkout.
- **Retries are safe:** `idempotency_keys`, `orders.idempotency_key`,
  `webhook_events (provider, provider_event_id)`, one gift-card redeem per
  order, unique provider order ids.
- **Money history is immutable:** order lines and totals are snapshots;
  refunds, wallet and gift-card ledgers are append-only.
- **Providers are data:** payment, fulfilment and shipping providers are
  `integration_providers` rows referenced by FK, so adding one needs no
  migration.

## 6. Creating the database

No database exists yet. The planned runner (tracked as
`TL-DB-MIGRATION-RUNNER`) applies `db/migrate/*.sql` in order to any
Postgres given by `DATABASE_URL_UNPOOLED`, records applied files in a
`schema_migrations` table, then runs the seed.
